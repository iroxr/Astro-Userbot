## Overview

Astro Userbot runs on your own Telegram account and is controlled by sending messages that start with a prefix (default `.`).
The core ships with **no features on purpose**: it only provides the plumbing (command routing, menus, persistence, error reporting, hot plugin install). You add what you need as plugins, written by you or generated by any AI model using the included [`PLUGIN_GUIDE.md`](PLUGIN_GUIDE.md).

It is designed to run for free on a Render web service, with all state stored in your own GitHub repository so nothing is lost when the host restarts.

## Features

- **Plugin-first.** One file = one feature. Adding a file adds its menu and commands automatically; removing it removes them.
- **Hot install.** Send a `.py` file to Telegram and run one command. No git, no manual redeploy.
- **Fail-safe loading.** A broken plugin is rolled back and reported; the rest of the bot keeps running.
- **Persistent by design.** Settings are saved to `data/settings.json` in your repo through a simple key-value store.
- **Events channel.** Command output and notifications are written to a dedicated channel (`قناة الاحداث`) that the bot finds or creates itself. The command message is deleted so your chats stay clean.
- **Private companion bot (optional).** Set `BOT_TOKEN` and a bot that answers only you appears: built-in `/start`, `/status`, `/commands`, plus plugin commands and push notifications.
- **Readable errors.** Failures are reported with the cause, the technical detail and a suggested fix.
- **Auto-generated menus.** `.الاوامر` lists every plugin group; `.اوامر <name>` lists a group's commands.
- **AI-friendly.** `PLUGIN_GUIDE.md` is a complete spec so any AI model can write a compatible plugin in one shot.

| Component | Version |

You also need a Telegram `API_ID` / `API_HASH` from [my.telegram.org](https://my.telegram.org) and a GitHub account.

## Quick start

### One-click deploy

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/YOUR_USERNAME/Astro-Userbot)

Two things are needed before you press the button:

**1. A private storage repository.** Create an empty **private** repository on your GitHub account and tick *Add a README* so it has a first commit. The bot saves its settings and installed plugins there (they may contain chat IDs and user IDs, so it must not be public). This is separate from the code repository the button deploys.

**2. Your credentials.**

| What | Where to get it |
|------|-----------------|
| `API_ID`, `API_HASH` | [my.telegram.org](https://my.telegram.org) → API development tools |
| `SESSION` | run `python gen_session.py` on your computer (see below) |
| `GITHUB_REPO` | your storage repository as `owner/repo` |
| `GITHUB_TOKEN` | fine-grained token limited to the storage repository with **Contents: Read and write** |

Press the button, fill in the five variables Render asks for, and deploy. Auto-deploy is off on purpose so updates to this project never redeploy your instance behind your back.

### Generate a session string

```bash
pip install telethon
python gen_session.py
```

Enter your `API_ID` and `API_HASH`, log in with your phone number and copy the printed `SESSION`.

### Verify

When the bot starts it creates the events channel (if it does not exist) and posts a status card there. Send `.الاوامر` from any chat to open the menu.

### Enable the private companion bot (optional)

1. Create a bot with [@BotFather](https://t.me/BotFather) and copy its token.
2. In Render, open your service → **Environment** → add `BOT_TOKEN` and save.
3. Open your bot in Telegram and send `/start`. Telegram does not let bots write first, so this one message links the bot to your account.

The bot ignores everyone except the account running the userbot. Check it with `.حالة النظام`.

### Manual deploy (without the button)

Copy this project to your own repository, create a **Blueprint** on Render from it (`render.yaml`), and fill in the same variables.

### Running locally

```bash
pip install -r requirements.txt
export API_ID=... API_HASH=... SESSION=... GITHUB_TOKEN=... GITHUB_REPO=owner/repo
python main.py
```

## Configuration

| Variable        | Required | Description |
|-----------------|:--------:|-------------|
| `API_ID`        | yes | Telegram API ID |
| `API_HASH`      | yes | Telegram API hash |
| `SESSION`       | yes | String session from `gen_session.py` |
| `GITHUB_TOKEN`  | yes | Fine-grained token with Contents read/write on the repo |
| `GITHUB_REPO`   | yes | Your **storage** repository, `owner/repo` (private) |
| `GITHUB_BRANCH` | no  | Defaults to `main` |
| `BOT_TOKEN`     | no  | Token of the private companion bot from @BotFather |
| `GROUP_LINK`    | no  | Link used on the status card title |
| `PREFIX`        | no  | Command prefix, defaults to `.` |
| `POST_TZ`       | no  | Display timezone, defaults to `Asia/Jerusalem` |
| `PORT`          | no  | Health server port, defaults to `10000` (Render sets it) |

Copy `.env.example` to `.env` for local runs. `.env` is git-ignored.

## Built-in commands

Commands are sent as normal outgoing messages from your account.

| Command         | Action |
|-----------------|--------|
| `.الاوامر`      | Main menu |
| `.اوامر <name>` | Commands of one group |
| `.الحالة`       | Status card |
| `.حالة النظام`  | Detailed system status |
| `.اضافة ملف`    | Install a plugin from an attached `.py` file |
| `.تحديث`        | Pull plugins from the repository and restart |
| `.اعادة تشغيل`  | Restart |

## Writing plugins

A plugin is a single Python file in `plugins/`:

```python
# Astro Userbot
from core.api import command, group, scope, ui

group("example")
store = scope("example")


@command("example on")
async def example_on(event, args):
    store.set("enabled", True)
    await event.edit("✅ on")
```

- Start from [`plugins/_template.py`](plugins/_template.py).
- Read [`PLUGIN_GUIDE.md`](PLUGIN_GUIDE.md) for the full rules, API reference and worked examples. It also contains a ready-made prompt for AI models.

### Installing a plugin

1. Send the `.py` file to any chat with the caption `.اضافة ملف` (or reply to the file with that command).
2. Run `.تحديث` to pull it and restart.

Plugin file names must match `^[A-Za-z][A-Za-z0-9_]*\.py$` and stay under 512 KB.

## Companion bot

With `BOT_TOKEN` set, a second Telegram client (your bot) runs next to the userbot. It is **private to your account**: messages from anyone else are ignored without a reply.

| Bot command | Action |
|-------------|--------|
| `/start`    | Welcome message, links the bot to your account |
| `/status`   | Same status card as `.الحالة` |
| `/commands` | Lists every bot command, including plugin commands |

Plugins add their own bot commands with `@bot_command` and can push messages to you with `bot_notify(text)`. See [`PLUGIN_GUIDE.md`](PLUGIN_GUIDE.md#15-companion-bot-commands). Without `BOT_TOKEN` nothing changes and plugins that use the bot should fall back to the events channel.

## Project structure

```
main.py                 entry point and startup sequence
gen_session.py          one-off helper to create the SESSION string
render.yaml             Render blueprint
requirements.txt
.env.example
PLUGIN_GUIDE.md         full plugin reference (humans and AI models)
core/
  __init__.py           env, paths, prefix, shared client
  api.py                the single import plugins need
  lang.py               all Arabic strings of the core
  errors.py             maps exceptions to readable causes
  ui.py                 menu and status cards, time helpers
  eventlog.py           events channel: find/create, post, edit, failures
  registry.py           command, group and listener registry
  dispatcher.py         outgoing-message router
  loader.py             plugin loader with rollback
  bot.py                optional private companion bot
  builtin.py            menus and system commands
  storage.py            GitHub Contents API wrapper
  settings.py           persistent key-value store
  runtime.py            restart handling
  keepalive.py          health server (/ and /health)
  state.py              runtime state
plugins/
  _template.py          starting point for a new plugin (never loaded)
data/
  settings.json         persistent settings (managed by the bot)
```

## Keeping the free tier awake

Render's free web services sleep after about 15 minutes without traffic. The core exposes `/health`; to keep the service awake, add a small self-ping plugin or use an external uptime monitor that calls your service URL every few minutes.

## Security

- **Your `SESSION` string is full access to your Telegram account.** Treat it like a password. Never commit it, share it or paste it anywhere public. Set it only as an environment variable.
- Keep `GITHUB_TOKEN` scoped to a single repository with Contents access only.
- Treat `BOT_TOKEN` like a password too. Regenerate it in @BotFather if it leaks.
- Keep your deployment repository **private**.
- Only install plugins you wrote or have read: plugins run with the full power of your account.
- If a secret leaks, terminate the session from Telegram → Settings → Devices and revoke the GitHub token.

## 🇵🇸 بالعربي

**Astro Userbot** بوت تيليجرام يشتغل على حسابك الشخصي، مبني على Telethon. النواة فاضية عن قصد: كل ميزة عبارة عن ملف بلغن واحد بتضيفه وقت ما بدك.

**المميزات**
- اضافة ملف = اضافة ميزة بقوائمها واوامرها تلقائيا، وحذفه بيحذفها.
- تثبيت البلغن من تيليجرام مباشرة: ارسل الملف مع `.اضافة ملف` ثم `.تحديث`.
- اذا بلغن فيه خطأ بيتعطل لحاله والبوت بيكمل شغل عادي.
- كل الاعدادات بتنحفظ في مستودع GitHub الخاص فيك، فما بتضيع مع اعادة تشغيل الاستضافة.
- كل نتائج الاوامر والاشعارات بتروح لقناة اسمها `قناة الاحداث` والبوت بينشئها لحاله، ورسالة الامر بتنحذف.
- ملف `PLUGIN_GUIDE.md` فيه كل قواعد كتابة البلغن، فاي نموذج ذكاء اصطناعي بيقدر يكتب بلغن متوافق.

**البدء السريع**
1. اعمل مستودع GitHub **خاص وفاضي** (فعّل Add a README) للتخزين. هذا غير مستودع الكود.
2. شغل `python gen_session.py` وخذ قيمة `SESSION`.
3. اعمل توكن GitHub (Fine-grained) بصلاحية Contents قراءة وكتابة على مستودع التخزين فقط.
4. اضغط زر **Deploy to Render** واملأ المتغيرات: `API_ID`, `API_HASH`, `SESSION`, `GITHUB_TOKEN`, `GITHUB_REPO` (مستودع التخزين).
5. ارسل `.الاوامر` لعرض القائمة.

**بوت التحكم الخاص (اختياري):** اعمل بوت من @BotFather، ضيف توكنه في Render بمتغير `BOT_TOKEN`، ثم افتح البوت واكتب `/start`. البوت بيرد عليك انت بس وبيتجاهل كل الناس.

**تنبيهات مهمة**
- قيمة `SESSION` بتعطي وصول كامل لحسابك، لا تشاركها ولا ترفعها على GitHub.
- ابقي المستودع خاص لان الاعدادات ممكن تحتوي ايديات محادثات ومستخدمين.
- ثبت فقط بلغنز انت كتبتها او قرأتها، لانها بتشتغل بكامل صلاحيات حسابك.
- استخدم البوت بمسؤولية والتزم بشروط تيليجرام. الاستخدام المفرط او المسيء ممكن يعرض حسابك للتقييد او الحظر.
